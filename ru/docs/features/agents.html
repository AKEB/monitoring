Агенты хостов

Бинарник monitoring-agent пушит телеметрию хоста на сервер примерно каждые 30 секунд.

Что отдаёт

  • Идентичность хоста, uptime, виртуализация
  • CPU, память/swap, диски, сеть
  • Docker-контейнеры при доступном сокете
  • Гости Proxmox VE при наличии /etc/pve
  • События auth, топ процессов

UI сервера

Admin → Servers → Create даёт AGENT_KEY_HASH. На карточке — графики, Proxmox, auth, ротация ключа, целевая версия.

Установка в Docker

docker run -d --name monitoring-agent --restart unless-stopped \
  --net host \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -e SERVER_HOST=https://monitoring.example.com/ \
  -e AGENT_KEY_HASH=... \
  akeb/monitoring-agent:latest

Установка без Docker (бинарник + systemd)

Скачайте с GitHub Releases или соберите:

go build -buildvcs=false -o monitoring-agent ./cmd/agent/
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -buildvcs=false -o monitoring-agent-linux-amd64 ./cmd/agent/
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -buildvcs=false -o monitoring-agent-linux-arm64 ./cmd/agent/

Типовая установка на хост (Proxmox, Debian, Raspberry Pi, LXC):

sudo mkdir -p /opt/monitoring-agent
sudo cp monitoring-agent-linux-amd64 /opt/monitoring-agent/monitoring-agent
sudo chmod 755 /opt/monitoring-agent/monitoring-agent
sudo tee /opt/monitoring-agent/.env >/dev/null <<'EOF'
TZ=Europe/Moscow
SERVER_HOST=https://monitoring.example.com/
AGENT_KEY_HASH=paste_agent_key_here
REPORT_INTERVAL_SEC=30
AUTO_UPDATE=true
EOF
sudo cp deploy/monitoring-agent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now monitoring-agent
journalctl -u monitoring-agent -f

Unit: deploy/monitoring-agent.service (подхватывает EnvironmentFile=-/opt/monitoring-agent/.env). Агент также читает .env рядом с бинарником. Полный список: Окружение → Агент.
