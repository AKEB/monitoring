Где Monitoring сильнее

  • MySQL + распределённые воркеры — control plane и проверки масштабируются раздельно; удобнее, когда один Node/SQLite уже тесен.
  • SSO и тонкий ACL — OIDC/OAuth, группы, права на объекты, наследование от папок, ACL секретов, impersonation, аудит.
  • История под вашим контролем — агрегаты и availability за 30 дней в своей БД; retention — выбор ops, а не план вендора.
  • Host-агенты — глубокие метрики серверов (systemd, Proxmox, listeners), а не только synthetic HTTP.
  • Широта протоколов + MCP — БД, messaging, SNMP/gRPC и автоматизация для AI-инструментов.
  • Интерактивные действия в мессенджерах — mute / take / resolve прямо из алерта.

Где выигрывают другие

  • Полировка status pages — HTML /status/{slug}/ и инциденты уже есть; у Kuma/SaaS сильнее кастомные домены и темизация.
  • Экосистема уведомлений — 90+ провайдеров Kuma и каталоги SaaS шире наших пяти каналов (Webhook закрывает часть кейсов).
  • Теги и embed-бейджи — у других обычны; у нас папки и бейджи в UI.
  • Zero-ops SaaS — UptimeRobot / Better Stack / Pingdom не требуют MySQL и воркеров.
  • Онбординг для homelab — у Kuma «один Docker» и красивый SPA для маленьких сетапов.

Подробно: Monitoring vs Uptime Kuma

Uptime Kuma — ближайший популярный self-hosted аналог. Если вы уже пользовались Kuma и упирались в лимиты, важнее всего вот это:

Плюсы Monitoring

  • SSO + доступы для команд и multi-tenant папок — не только общий admin-логин.
  • MySQL вместо SQLite — привычные бэкапы/репликация; меньше боли при росте мониторов, событий и агрегатов.
  • Масштаб после ~100 мониторов — удалённые воркеры снимают нагрузку проверок с UI/API; у Kuma при росте часто становится тяжело, когда всё живёт в одном процессе Node + SQLite.
  • Более полезная длинная история — суточные агрегаты и availability 30д в своём MySQL, а не только раздувающееся локальное heartbeat-хранилище.
  • Host-агенты + MCP для инфраструктуры и автоматизации.

Плюсы Kuma

  • Более богатая темизация status pages и кастомные домены (у нас уже есть /status/{slug}/ и инциденты).
  • 90+ каналов уведомлений из коробки.
  • Теги, embed SVG-бейджи, много языков UI.
  • Очень быстрый старт «один Docker» для маленьких лабораторий.
Про производительность Мы описываем архитектурное отличие (распределённые воркеры + MySQL vs single-node SQLite). Синтетические RPS здесь не публикуем — интервалы и сеть обычно важнее.
