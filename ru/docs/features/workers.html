Воркеры

Воркеры — удалённые Go-процессы: забирают задания и отдают результаты (протокол 2.0+).

Управление

  • CRUD: название, активность, версии протокола/воркера
  • Таймауты и число потоков
  • Секрет WORKER_KEY_HASH
  • Привязка мониторов и Docker-хостов
  • Restart и целевая версия для автообновления с GitHub

Запуск в Docker

docker run -d \
  --name monitoring-worker \
  -e SERVER_HOST=https://your-monitoring-server.com \
  -e WORKER_KEY_HASH=your_unique_worker_key_here \
  akeb/monitoring-worker-go:latest

В Docker лучше AUTO_UPDATE=false и обновление тегом образа.

Запуск без Docker (бинарник + systemd)

Скачайте релиз с GitHub Releases или соберите:

go build -buildvcs=false -o monitoring-worker ./cmd/worker/
# cross-compile:
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -buildvcs=false -o monitoring-worker-linux-amd64 ./cmd/worker/
GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -buildvcs=false -o monitoring-worker-linux-arm64 ./cmd/worker/

Установка в /opt/monitoring-worker с unit deploy/monitoring-worker.service:

sudo mkdir -p /opt/monitoring-worker
# From GitHub Releases: monitoring-worker-linux-amd64 or arm64
sudo cp monitoring-worker-linux-amd64 /opt/monitoring-worker/monitoring-worker
sudo chmod 755 /opt/monitoring-worker/monitoring-worker
sudo tee /opt/monitoring-worker/.env >/dev/null <<'EOF'
TZ=Europe/Moscow
SERVER_HOST=https://monitoring.example.com/
WORKER_KEY_HASH=paste_worker_key_here
PROTOCOL_VERSION=2.0
AUTO_UPDATE=true
EOF
sudo cp deploy/monitoring-worker.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now monitoring-worker
journalctl -u monitoring-worker -f

Воркер читает .env из рабочей директории или рядом с бинарником. Полный список: Окружение → Воркер.
