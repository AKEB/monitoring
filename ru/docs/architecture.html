Архитектура

Monitoring — это control plane (сервер) и два типа периферии: воркеры, которые забирают задания проверок, и агенты, которые пушат телеметрию хоста.

Поток данных

sequenceDiagram participant UI as Web_UI participant S as Server participant W as Worker participant A as Agent participant N as Notify UI->>S: Мониторы и ACL W->>S: get jobs protocol 2.0 S-->>W: список заданий W->>W: Проверки W->>S: state результаты A->>S: report метрики S->>S: События статусов S->>N: Алерты UI->>S: Дашборд WebSocket

Хранение

  • MySQL — конфигурация, события, агрегаты
  • Memcached — короткоживущие кэши
  • Сырые логи агрегируются; детали чистятся примерно за 24 часа

Зачем разделять воркеры и агенты

Воркеры отвечают: «доступен ли сервис из этой сети?». Агенты — «что происходит на машине?». Можно держать много воркеров по миру и агентов на закрытых хостах без входящих портов к серверу.
