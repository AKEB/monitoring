Status pages

Publish a customer-facing HTML status page at /status/{slug}/ without exposing the admin UI or turning on the Status API for every monitor.

Membership ≠ api_enabled Adding a monitor to a status page only controls the public HTML page. It does not put that monitor into GET /api/v1/status/. Keep Status API opt-in via the monitor’s api_enabled flag.

What visitors see

  • Overall state: All systems operational / Partial outage / Major outage / Under maintenance
  • Monitor list with 24h heartbeat bars and uptime percentage
  • Published incidents (title, message, severity, timestamps)
  • Optional custom header HTML and footer text
  • EN / RU language switch (?lang= or cookie)

Which monitors appear

Only leaf monitors are listed: not a folder, enabled (status=1), and all ancestor folders enabled. Empty folders and disabled branches stay hidden.

Admin

  1. Open Status pages in the admin menu (ACL-gated).
  2. Create a page: slug, title, description, theme, published flag.
  3. Attach monitors you can read (multi-select respects ACL).
  4. Add / edit / delete incidents from the page editor.
  5. Share https://your-host/status/{slug}/ when published.

API & MCP

Management API v2 and MCP expose statuspages CRUD (including membership and incidents). See API & MCP and OpenAPI at /api/docs/.
