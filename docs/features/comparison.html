Where Monitoring is stronger

  • MySQL + distributed workers — control plane and check execution scale separately; better fit when you outgrow a single Node/SQLite box.
  • SSO and fine-grained ACL — OIDC/OAuth, groups, per-object permissions, folder inheritance, secret ACLs, impersonation, audit.
  • History you control — aggregates and 30-day availability in your database; retention is an ops choice, not a vendor plan.
  • Host agents — deep server metrics (including systemd, Proxmox, listeners), not only synthetic HTTP.
  • Protocol breadth + MCP — databases, messaging, SNMP/gRPC, and first-class automation for AI tooling.
  • Interactive messenger actions — mute / take / resolve from the alert itself.

Where others win

  • Public status pages polish — we ship HTML /status/{slug}/ + incidents; Kuma/SaaS still lead on custom domains and richer theming.
  • Notification ecosystem — Kuma’s 90+ providers still beat our nine native channels (Email/Discord/Slack/ntfy + messengers + Webhook).
  • Badge theming depth — we ship shields-style /badge/{hash}.svg; Kuma still has richer badge variants.
  • Zero-ops SaaS — UptimeRobot / Better Stack / Pingdom need no MySQL or workers to run.
  • Homelab onboarding UX — Kuma’s single-container SPA is hard to beat for tiny setups.

Deep dive: Monitoring vs Uptime Kuma

Uptime Kuma is the closest popular self-hosted peer. If you already used Kuma and hit limits, these differences matter most:

Monitoring advantages

  • SSO + access control for real teams and multi-tenant folders — not just a shared admin login.
  • MySQL instead of SQLite — standard backups/replication; less pain as monitors, events, and aggregates grow.
  • Scale past ~100 monitors — remote workers take check load off the UI/API process; operators often see Kuma slow down when everything shares one Node + SQLite process.
  • Longer useful history — daily aggregates and 30d availability in MySQL you own, instead of an ever-growing local heartbeat store.
  • Host agents + MCP for infrastructure depth and automation.
  • Monitor tags + SVG badges — Bootstrap pills on monitors/folders and public /badge/{hash}.svg.

Kuma advantages

  • Richer status page theming and custom domains (we ship /status/{slug}/ + incidents already).
  • 90+ notification providers out of the box.
  • Many UI languages via Weblate (we ship EN/RU).
  • Extremely fast “one Docker” start for small labs.
About performance claims We describe the architectural difference (distributed workers + MySQL vs single-node SQLite). We do not publish synthetic RPS numbers here — your interval mix and network paths dominate real results.
